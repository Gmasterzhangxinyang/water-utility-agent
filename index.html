一
背景与目标

1问题背景

水务政府系统面临一个核心矛盾：用户问题种类繁多、持续新增，而知识库更新依赖人工维护，效率低、覆盖慢。传统 RAG 系统只能回答已有文档中明确存在的内容，对于用户的实际问题无法回答时，缺乏自动化的知识获取机制。

核心理念

不要试图预先拥有所有答案——而是要建立一个能自动发现知识缺口、并通过人工反馈持续补全的系统。这正是 MiniMax M2.7 自进化架构的核心思想。

2核心概念：从 M2.7 自进化到水务知识库

MiniMax M2.7 的自进化，本质是一个"AI 执行 → 人类审核 → 知识固化"的循环。我们的水务知识库系统完全同构：

M2.7 自进化步骤 水务知识库对应 说明
Step 1 — 设计实验 识别知识盲区 用户问了 Agent 回答不了的问题
Step 2 — 执行（多 subagent 并行） Agent 检索知识库 + 生成候选答案 并行执行：意图识别 / RAG 检索 / 答案生成
Step 3 — 评估 置信度评分 检查答案是否有据可查、是否在已知领域
Step 4 — 人工审核（Human-in-the-loop） 水务专员审核 提供权威答案，标注法规来源
Step 5 — 决策 知识入库 / 索引更新 人工答案固化为知识库条目
Persistent Memory（分层） 知识库三层架构 raw_qa → reviewed → canonical
Hierarchical Skills 分域管理 水质 / 管网 / 计费 / 应急 / 法规
Sigmoid 路由（独立评分） 置信度路由 任一维度低于阈值 → 升级人工，不强制二选一

M2.7 的 sigmoid 路由核心启示：独立评分 ≠ 竞争。多维度同时低于阈值才升级人工，任何单一高分都不能掩盖其他维度的不足。

四
置信度路由

5置信度路由：Sigmoid 独立评分机制

M2.7 用 sigmoid 而非 softmax 做 expert 路由——核心原因是 独立评分，不强制 winner-takes-all。我们的置信度路由继承同一逻辑：三个维度独立评估，任一低于阈值即升级人工，不做零和竞争。

评分维度

维度 1
检索相关度
retrieval_relevance
向量检索结果与问题的语义相关程度
维度 2
答案有据性
answer_groundedness
生成答案是否能在检索结果中找到依据
维度 3
领域覆盖
domain_coverage
问题是否落在已知知识域范围内

路由逻辑实现

def route_question(question: str,
                retrieved_docs: list[Doc],
                generated_answer: str) -> str:
    # ─── 三个独立评分维度 ───
    scores = {
        "retrieval_relevance": score_retrieval(question, retrieved_docs),
        "answer_groundedness": score_grounding(generated_answer, retrieved_docs),
        "domain_coverage":    check_domain_coverage(question),
    }

    # ─── 分域阈值（法规类最严格）───
    domain_thresholds = {
        "法规": 0.85,
        "水质": 0.80,
        "应急": 0.80,
        "管网": 0.70,
        "计费": 0.70,
    }
    threshold = domain_thresholds[detect_domain(question)]

    # ─── 任一维度低于阈值 → 升级人工 ───
    # Sigmoid 独立评分思想：高分不能掩盖低分
    if any(s < threshold for s in scores.values()):
        return "escalate_to_human"
    return "answer_directly"
五
自进化闭环

6自进化闭环：从问答数据到知识增长

冷启动

建立初始知识库

导入水务系统现有文档、操作手册、法规文件，建立初始 RAG 索引。

  • 批量导入现有文档（PDF / Word / HTML）
  • 建立向量索引（Chroma / Milvus）
  • 定义五大知识域分类体系
  • 配置各域置信度阈值
运行积累

持续吸收人工知识

系统运行后，用户问答自动沉淀，人工审核将知识逐层晋升。

  • 用户问答自动入库 → raw_qa 层
  • 专员审核 → 升级为 reviewed 层
  • 每周自动聚合相似问题，生成标准 FAQ
  • 高频高质条目自动晋升 canonical 层
知识蒸馏

用数据驱动模型进化

当知识库积累到一定规模后，可以选择进一步的知识进化策略：

  • 选项 A（推荐）：扩充 RAG 索引，低成本持续迭代
  • 选项 B：用 Q&A 对 fine-tune 小模型（Qwen2.5-7B）
  • 选项 C：定期更新 embedding 模型，提升检索精度

先把人工答案收集起来，再用这些数据驱动模型进化——
这正是 M2.7 bootstrap 循环的本质。

七
政府水务项目特殊要求

8四大政府合规要求

01 可审计性（最重要）

每条答案必须能追溯：哪位专员审核、引用哪条法规编号、何时更新。审计日志全程记录，不可在事后篡改。

02 准确性优先于覆盖率

水质、应急、安全类问题宁可升级人工，绝不给出低置信度答案。宁可拒答，不可错答。

03 数据不出境

政府数据必须在本地处理。推荐 Qwen2.5-72B / DeepSeek-V3 本地部署。MiniMax M2.7 API 需确认合规路径后再用。

04 分层权限管理

普通专员：审核 + 填写答案。主管：审批法规类条目。系统管理员：配置阈值 + 触发晋升规则。
